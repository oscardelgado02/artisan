The workflow

      
One loop. Two sides.

      
The human designs, the agent implements, and artisan tracks every change in both directions.

      

        

          01
          
artisan scan

          
C# → diagram: every class, all six UML relations, layered layout, notes preserved. Re-scans merge; nothing you did is lost.

          →
        

        

          02
          
You redesign

          
Drag, rename, rewire, add classes, write notes. Notes bind the agent — they end up in the report it executes.

          →
        

        

          03
          
artisan diff

          
Your diagram edits become a markdown report: notes first, renames stay renames, additions are scaffolded.

          →
        

        

          04
          
The agent implements

          
/artisan-scaffold and /artisan-implement turn the report into code. Existing members are never touched.

          →
        

        

          05
          
The agent proposes

          
/artisan-architect lets the agent suggest structure. Its changes appear amber in your editor until you confirm.

          →
        

        

          06
          
artisan ack

          
You confirm, both sides sync, and the next scan keeps the picture current. Then the loop runs again.

        

      

    

  


  
  

    

      

        

          the human
          
You make the decisions

          
    
            
  • Design the architecture in a fluid, click-to-edit canvas
    • 
            
  • Every class, member and relation carries a note the agent must honor
    • 
            
  • Review the agent's proposals in amber — accept or push back
    • 
            
  • Dictate changes from the terminal with artisan add/edit/remove
    • 
          

          
The agent reads the architecture from .artisan/diagram.puml before touching code.

        

        

          the agent
          
The agent does the typing

          
    
            
  • Reads a markdown diff report instead of guessing intent
    • 
            
  • Renames are refactored — never delete-and-recreate
    • 
            
  • Existing members are never modified; additions scaffold or implement
    • 
            
  • Its own architecture ideas wait for your confirmation
    • 
          

          
No pack needed — any agent that can run artisan diff works.

        

      

    

  


  
  

    

      
Two packages, one hub

      
One picture, three repos

      

        

          GitHub · the hub
          
artisan

          
Installer and slash-command packs for opencode, Claude Code and Codex. The entry point.

          

          github.com/oscardelgado02/artisan →
        

        

          npm · the editor
          
artisan-uml

          
The class diagram editor. One self-contained HTML file in your project, a web app in the browser, a layout engine you can import.

          

          
editor.artisan-uml.devnpm

        

        

          npm · the CLI
          
artisan-uml-cli

          
scan, diff, mark-ai, ack, status, add/edit/remove, editor, serve — everything the loop needs.

          

          
cli.artisan-uml.devnpm

Get started

      
Live in your project in two minutes

      

        
installer

        
$ git clone https://github.com/oscardelgado02/artisan
$ cd artisan
$ ./install.sh
# installs artisan-uml-cli globally + copies the six /artisan-* commands
# into opencode, Claude Code and Codex command folders
$ cd your-project
$ artisan scan

      

      
Don't use the packs? npm i -g artisan-uml-cli and point any agent at artisan diff — full guide.

    

  


  
  

    

      

        
Why this exists

        
Agents create architecture. Nobody asked them to.

        
    
          
  • Drift: new classes, new abstractions, rewired dependencies — nobody decides, everybody pays.
    • 
          
  • No picture: the architecture lives only in the last prompt that worked.
    • 
          
  • Lost speed: fighting drift costs more than the speed agents give back.
    • 
        

      

      

        

          
As a Software Engineer, I like to plan the architecture of my projects with class diagrams. I wanted to bring them closer to the way we build software today, hand in hand with agentic workflows, to make coding fun again.
